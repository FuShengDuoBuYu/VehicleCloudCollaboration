# 云端辅助恢复实现计划

依据：../specs/2026-10-10-cloud-assisted-recovery-design.md；用户已明确批准实现，2026-10-10。

1. 严格 recovery 合同及 Realtime 1–3 帧：先协议回归，再实现，兼容原单帧合同。
2. 新增当前证据候选、近期帧缓存、持续停滞/异步请求/单步恢复模块；先故障与状态测试。
3. 接入 onboard 最终执行截止、故障撤销、配置和记录；验证虚拟 PWM 与停止，不接真实电机。
4. 运行回归、少量历史图真实 API 组件测试；保留输入哈希、原始响应与失败记录。
5. 一次独立审查、修正问题，写部署与实验交接报告。

Ruling: 用户批准当前代码内联实现；当前仅设计文档未跟踪，无并行文件修改。原目录顺序编辑，不另建会改变交付位置的工作树，不提交/推送，等待最终 review 后的明确发布授权。大范围重构延期。
Ruling: 恢复使用独立控制器，但所有实际指令仍通过同一个最终 driver/截止/看门狗。新配置与旧 cloud_arbitration 互斥，保留旧接口。
Ruling: 官方多图传输只对 recovery 合同开放；旧 fast 合同保持单图。未证明多图更优，保持 single/sparse3 配对开关。
