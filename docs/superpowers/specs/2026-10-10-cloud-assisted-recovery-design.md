# 持续感知停车的云端辅助恢复设计

日期：2026-10-10（Asia/Shanghai）。状态：用户已批准并完成本地实现/无电机验证，未执行实车。原始授权：“可以，你来做吧，车端我到时候直接拉取最新代码然后再实车测试”。基线：`bd6fe9c88f6c441eda2f4abbac14054ba3e9570b`。负责角色：本地实现与评测；车端负责部署与现场验证。大范围重构推迟至链路跑通之后；沿用先前不提交/推送要求，发布待代码review后明确授权。交付见 `coordination/2026-10-10-cloud-recovery-implementation.md`。

## 用户目标及成功标准

当前YOLO道路/车道线与局部路径逻辑在白色标记、弯道和近场漏分时反复停车。希望停车时由云端分析原因、提出能被车端使用的建议，车端据此尝试摆脱停滞并重新进入本地驾驶。

本轮目标是实现真实可调用、可记录、可在无电机回放中执行完整状态变化的协同链路。不是只接一个返回“继续”的API，也不以云端输出直接替换全部车端判断。真实脱困成功、不压线和完整圈仍以新实车运行验证。

## 已确认的接入缺口

1. 当前车端profile关闭cloud_arbitration，入口要求road-scene-v1；用户已选定的road-observation-fast-v1不能直接接入。
2. `CloudCoordinator.filter`遇到local_safe=false始终返回stop，因此即使云端认为白线可跨越，也不能改变导致停车的本地解释。
3. `onboard.py`将cloud motion_allowed作为StationaryCornerRuntime的external_motion_allowed，后者把它计入local_safe，再将local_safe返回云仲裁积累恢复证据。云端pending/validating使该值为false，可能造成循环等待。必须分开“独立的当前本地证据”和“叠加云门禁后的最终许可”。
4. 本地单步、当前颜色/路径、IMU、独立执行截止及记录机制已具备，可复用；没有必要先重构整个onboard.py。

## 方案比较与选择

| 方式 | 作用与代价 | 决定 |
|---|---|---|
| 云端只返回继续/停止 | 开发量小，但没有纠正白线/几何解释，容易维持原停滞或粗暴绕过全部限制 | 不采用 |
| 云端解释语义并选择车端受限候选 | 云端处理语义歧义；车端重算当前候选，保留局部执行与重新观察 | 第一版采用 |
| 云端生成自由路线/像素掩码/动作序列 | 表达更强，但几何校验、坐标/时序关联与执行验证范围显著扩大 | 后续评测后扩展 |

这里的候选由当前观测构造，不是固定绕圈时间表。第一版支持短直行和小幅右旋，覆盖现有白标记和右弯问题；不凭云建议执行倒车、任意左右绕障或长距离运动。

## 输入选择：当前帧为依据，近期两帧为辅助

工程默认使用**最多三张同一运行的原始画面**：当前模型消费帧，以及约1秒、2秒前的不同消费帧。环形缓存只收集与YOLO输出匹配的原始图、序号与捕获时钟；不连续上传视频，不用网页叠加图替代原始输入。短历史不足时明确提供一帧或两帧，不复制同一帧伪造时间变化。

历史帧让云端判断“由直道逐渐接近右弯”“白色标记刚进入视野”等变化；当前帧决定当前建议。不得从旧帧推断现在被遮住的地面一定可通行。帧按旧到新提交，并在上下文中提供顺序、相对时间、当前帧序号；其中候选只对应最新帧。

上下文提供：run/event/frame ID、停车原因代码与持续时间、当前模型是否新鲜、局部路径/颜色/障碍摘要、候选ID和类别、当前角度变化等必要字段。敏感配置不上传；车辆状态和路牌文字都是数据，不能作为覆盖系统规则的指令。候选可用单独的标记图说明，但必须保留原图且记录派生方法；是否启用标记图由后续固定输入评测决定，初版先用原图与明确候选描述。

传输仍为qwen3.8-omni-flash-realtime独立Manual WebSocket会话。官方支持连续JPEG输入，建议1张/秒；每张Base64≤256KiB，提交图像前需先有音频输入，commit同时提交音频/图像。扩展现有单图实现为1–3帧，保留合成静音的明确说明及usage费用。按官方推荐节奏提交，三帧会增加传输等待；用户已明确2秒不是硬截止。网络总预算默认30秒、可配置。

这只是工程选择，不宣称三帧已经比单帧准确。保留single/sparse3两个配置，用相同事件、相同提示/合同做配对比较，评价语义正确率、候选选择、拒绝率、总响应时间和usage成本。实车最新原始资料未同步且SSH上次超时，取得数据前不能虚构此比较的结论。单帧退化必须是缺历史时明确记录的策略，不在失败后静默追加另一模型调用。

## 输出合同：road-recovery-v1

保留通用简短观测合同，车端恢复任务显式选择新合同。建议输出固定JSON：

```json
{
  "schema_version": "road-recovery-v1",
  "assessment": "white_marking",
  "recommendation": "try_candidate",
  "candidate_id": "candidate_1",
  "uncertain": false,
  "hazards": [],
  "reason": "当前白色标记位于黄线内，可重新检查短直行候选"
}
```

- assessment：white_marking、right_corner、road_model_gap、obstacle、unknown。
- recommendation：hold或try_candidate。hold时candidate_id必须为null；try_candidate必须引用该事件实际提供的候选ID。
- uncertain为严格布尔；不确定或存在冲突危险时不能产生执行许可。hazards为固定枚举集合，不能任意写动作。reason为最多80字符的解释，只用于记录/界面，不解析成控制指令。
- 禁止额外字段、非法枚举、未知候选、错误事件关联、非有限数、Markdown外壳或不完整响应；全部失败保持停车。
- 云端不返回PWM、时长、固定角度、任意坐标路径或“解除所有门禁”。执行约束由本地配置给定。
- 本地envelope绑定事件、候选版本、输入hash、模型/提示/合同版本和会话/响应ID，不依赖模型正确复述身份。

## 触发与恢复状态机

`LOCAL_DRIVING → STALL_CONFIRM → CLOUD_PENDING → REVALIDATE → PROBE_STEP → OBSERVE → LOCAL_DRIVING / CLOUD_PENDING / HOLD`

持续停车起始候选参数：1秒且至少3个不同的新鲜观测。它是工程去抖参数，需后续标定，不是长尾真值。只对道路/车道标记/路径几何/弯道状态等可分析的停滞计时；正常小步停顿、出口确认、模型预热、云等待、操作取消或传感器失效不触发重复请求。

每个停滞事件最多一个在途请求；场景显著改变或用户结束则使旧结果失效。失败采用有界冷却和每事件有限尝试，初始最多3次；达到上限维持停车并给出明确原因，避免无人察觉的持续付费循环。恢复运动并取得连续有效本地观测后才关闭事件，不因一次云回复就重置尝试数。

云端结果到达后先校验合同/身份/候选与当前场景，再用最新帧重建候选。历史图片、过期掩码或请求时已有的几何不能独自授权当前动作。当前新鲜度、目标/黄线、IMU、操作者会话、看门狗、记录健康检查必须通过。

选择通过后执行**一个**本地短步，沿用现有PWM上限30、0.15秒/5°上限（先达到者结束）和停止后重新观察；正常巡航才沿用原本的连续驾驶逻辑。云许可不能缓存为持续运动许可，也不能按旧建议连续盲走。短步后重新评价是否获得有效本地路线；仍停滞则在事件预算内再次分析当前新图。

## 让云端实际影响恢复，而不保持原来的死锁

将证据分为以下两层，并以原因码而非人类可读字符串做分支：

1. **不可由云端放行的执行条件**：操作取消/会话失联、看门狗、传感器或帧失效、记录失败、明确目标阻挡、实际黄线侵入等。云回复只能解释，不能覆盖。
2. **可以提出替代解释的感知/规划条件**：白色纹理被lane头错误排除、当前局部路线选择/拟合失败、转向阶段保守锁定等。云端选择对应候选后，本地仅重算该项语义解释和局部候选；其它条件保持独立。

白线场景：请求提供“当前YOLO road支持、同帧颜色支持、未跨黄线、无目标占用”的短直行候选。云端确认是可跨越白色路面标记后，只允许候选所覆盖的当前白色排除得到重新解释，不能删除全部lane或黄色像素。

右弯场景：请求提供当前近地面/可见黄线约束/右出口支持下的小幅右转候选。云选择右弯后，可解除仅由局部路线或阶段判据造成的停滞，再由同一当前几何和IMU限制完成短步。

近场道路完全缺失、没有足够独立当前几何或存在明确障碍时可能没有候选，此时模型可以说明原因但不能保证脱困。不能以“云端说有路”为由把所有未知像素填成可行驶地面。后续若要让云端提供空间区域，需另外定义并验证坐标和当前图像配准合同。

尤其修复循环依赖：独立本地证据先计算，云状态消费该证据；最终执行层合并本地、云和硬件条件。云等待不得污染用于判断“本地是否恢复”的证据本身。

## 验证与交付

1. 合同/协议：1–3帧顺序、捕获时间/候选绑定、输入上限、原始事件/费用留证、错误/迟到/错事件/重复响应/未知候选、超时与预算；真实本机WebSocket验证。
2. 状态：持续停车触发；正常小步等待不触发；云许可不污染本地恢复；只放行一个通过当前校验的短步；图像更新/取消/障碍/黄线/IMU/记录故障随时撤销；三次上限。
3. 无执行器完整运行：合成/保存图像加受控云输出，覆盖白标记与右弯恢复，检查实际传入最终driver的虚拟PWM和停止时序，而不仅单测JSON解析。
4. 真实API：用已有获准历史场景做少量调用，比较单帧/稀疏历史输入，保存所有成功与失败。没有新实车数据时明确结果边界。
