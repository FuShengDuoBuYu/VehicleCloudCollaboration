# 车云协同论文研究与车端工程

本技能是当前车端仓库的工作方法。协作、授权和数据保护的统一规则见仓库根 [AGENTS.md](../../../AGENTS.md)；当前事实见 [PROJECT_INDEX.md](../../../PROJECT_INDEX.md)。不要把技能本身当作某个架构版本或实验成功的证据。

## 定位任务

1. 先读索引中与任务相关的内容，再核对当前源码、配置和运行证据；区分当前实现、历史版本、撤回方案和论文目标。
2. 模块职责见 [当前架构](../../../docs/architecture/current.md)，启动和副作用见 [运行说明](../../../docs/operations/runtime.md)，原数据位置见 [实验注册](../../../experiments/README.md)。统一使用 `./vehicle` 的命令入口。
3. 本机是车端项目，不假定电脑论文正文、完整实验计划、开题/中期材料已同步。需要这些材料时指出准确缺口，并继续现有材料能支持的工作。
4. 跨主机/聊天交接使用同级 [thesis-handoff](../thesis-handoff/SKILL.md)，不在本技能重复维护交接规则。

## 工程与实验分析

- 检查实际活动profile和调用链，不能根据脚本名字、旧Pi记录、计划文档或网页截图推断当前运行状态。
- 在原数据的基础上建立run/事件级关联；使用完整路径区分同名run副本，记录配置、模型、源码身份、帧序号、时间基准及缺失项。
- 原始、派生、合成反事实数据分别标明。派生分析用新目录，记录输入哈希、变换方法、参数、随机种子和输出身份。
- 先用无执行器回归、故障注入和冻结输入回放定位问题；这些验证不能证明车辆刹停距离、转弯成功或整圈完成。
- 正式实车实验前冻结代码、模型、标定、阈值和协议；正式测试数据不参与调参。样本划分和重采样以独立run或事件为单位，不能把相邻帧当独立样本。
- 论文所述端到端运行能力，需要相应版本在实车上的原始记录及重复验证；缺失时明确证据范围，不补写实验结果。

## 论文证据与表述

- 每项重要定量结论应可回到代码版本、配置、输入/run ID、原日志和分析方法。使用项目索引中的证据等级区分实现、开发验证、历史演示和计划。
- 可以改善写作、重新计算统计量并给出有依据的推论；不得虚构测量、样本数、成功率、基线、引用或已完成状态。
- 以实际可获得的开题/中期材料和用户最新要求核对研究范围。章节结构、模板字体、参考文献库等电脑端要求由对应论文项目维护，不在本车端技能复制易过时的另一套规则。
- 文献型任务优先查用户资料及原始论文、官方资料，核验出处与适用条件；不同硬件、数据集、协议的结果不能直接宣称公平比较。
- 实验图使用真实记录，注明run、帧/时间与分析版本。架构图可以抽象表达，但必须区分已实现模块、外部服务与规划内容；示意图不能充当实验结果。

重要事实按日期和命令/证据来源更新PROJECT_INDEX；本次任务结果记录到coordination。可复用方法才进入技能，避免把阶段进度和完整聊天历史积累在此。
