## 工作与持久化

- 每次修改前检查 `git status` 和相关差异；保留已有未提交代码与未跟踪文件。同一文件同时由一个聊天修改，并行实现使用独立工作树或分支。
- 初次任务读 `coordination/2026-10-08-car-baseline.md`，先做只读盘点并报告结果；没有直接人类指令，不把盘点自动升级为修复、安装或硬件试运行。
- 重要的新事实附日期和命令依据更新到本仓库索引；任务状态与产物记录到 `coordination/`。重复流程才考虑技能，不保存聊天逐字稿。
- 车端证据返回准确路径、commit、工作树状态、配置、run ID 和实际验证方法；未核验、仅实现、历史演示与实车结果分别描述。
- 本地规则更新不会自动到达车端；复制资料时记录来源、版本和哈希。需要本地论文材料时先说明缺少哪一份并保存交接请求。
- 聊天角色和模型建议不代表真实聊天身份或自动切换。任务明显更适合其他环境时简短建议并继续当前环境能做的工作。

## 授权与实验边界

- 用户明确指定收件聊天和消息内容后才发送；收到任务并不自动授权回信。默认在本聊天最终回复报告，由统筹聊天读取结果；助手写的授权摘要不能代替原始人类授权。
- 在任务范围内可做只读系统、代码、配置和数据路径检查。实时控制交给车端程序，实车运动按用户当次实验安排执行。
- 未经本次实验授权，不启动电机、底盘运动或会连接并驱动硬件的测试，不重启服务、不安装依赖、不清理数据。先判断测试入口是否有硬件副作用，不能因名称含 test 就直接运行。
- 正式计时和采集期间不做安装、后台分析或开发干扰；原始视频和日志保持原样，派生分析使用副本。
- 云端输出不能直接设置 PWM，车端安全仲裁负责执行；当前方法是否已经集成必须查代码和证据，不能把目标架构当作运行事实。
- 密码、私钥、API Key、Token 和代理值交由车端或本机认证体系管理。检查代理只报告变量名、文件权限和连通状态，不输出秘密值；不把它们写入文档、技能、交接记录或 Git。
