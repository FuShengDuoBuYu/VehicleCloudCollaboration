| S1 | 底盘遥测 | 底盘串口 | IMU 角度/时效用于短转约束；编码器、UART 等用于记录和复盘 |

V5/V7 的部分职责由同一个恢复状态机实现，可以在图上合并为“云辅助恢复与决策仲裁”。不要为绘图方便创造两个互相等待或重复授权的控制器。

黄线、障碍、候选几何等约束分布在证据构建、局部控制和恢复判断中，执行时还要复核时效与截止。可以抽象为贯穿决策与执行的“车端安全约束”，但不要暗示仅靠最后一个模块才首次发现障碍。

## 4. 三条必须画清楚的链路

### 4.1 正常本地控制闭环

`相机 → YOLOPv2 → 当前局部证据 → 本地控制提案 → 车端融合入口 → 最终执行约束 → 底盘 → 新一轮观测`

正常驾驶不需要等待云端，不要求每周期停车。融合入口也处理正常本地提案。常规局部控制与网络交互解耦，云端不是串行阻塞在每一帧控制之前的必经步骤。

### 4.2 云辅助恢复支路

1. 本地感知/规划持续停车，使用不同的新鲜观测确认停滞，排除正常短步停顿等情况。
2. 车端依据当前图像与几何约束生成受限候选，并准备当前帧和可用的近期原始帧。
3. 异步上传图像、停车上下文和候选，云端分析场景并选择候选或建议保持停车。
4. 回复到达车端后校验合同、事件关联、时效、候选和危险信息。
5. 等待并使用比请求输入更新的当前观测，重新核验候选；请求时的旧画面不能直接授权当前动作。
6. 通过约束时执行一个短步；随后停车/重新观察，再判断能否恢复本地控制。否则保持停车或在预算内重试。

云建议影响的是受限候选的语义选择，不是直接覆盖本地几何判断。当前候选主要为短直行和小幅右旋，不是任意左右变道、倒车、绕障轨迹或自由动作序列。

硬条件不允许运动但图像可供分析时，可发起“仅观察”请求。此类回复无论如何不能转换成运动授权，应在详细图注说明，不必额外增加大量主图节点。

### 4.3 实验数据链

`采集 / 感知 / 本地决策 / 云交互 / 最终执行 → 原始实验记录 → 运行与版本关联 → 离线回放和分析 → 论文指标与图表`

必须保留的记录包括：原视频、模型实际消费帧及掩码、逐周期控制日志、最终执行输出、原始 UART/遥测、雷达/深度记录、云输入图像、请求/回复、融合决策和实际应用日志。

关联身份包括：`session_id`、`run_id`、`event_id`、帧序号、捕获/接收时间、代码/配置/模型/标定版本。采集时间与接收时间不同；不同 boot 的单调时钟不能直接拼接。

离线回放读取冻结观测和可匹配的历史云回复，生成派生结果，不覆盖原始实验。它不改变视频下一帧，不能预测新的物理轨迹，也不能替代正式实车成绩。

## 5. 箭头与消息说明

| 起点 → 终点 | 箭头可用名称 | 应表达的信息 |
|---|---|---|
| V1 → V2 | 原始图像 | 图像、帧序号、捕获时间 |
| V2 → V3 | 同帧感知结果 | 道路/车道掩码、目标框与其匹配原图 |
| V3 → V4 | 局部可行性 | 路径/通道、边界与障碍约束、观测有效性 |
| S1 → V4 / V5 / V8 | 姿态与时效 | 按动作需要检查 IMU；不要把编码器画成已实现的 SLAM 位姿 |
| V4 → V7 | 本地控制提案 | 动作、差速、原因、置信度与截止时间 |
| V3 / V4 → V5 | 停车上下文与当前证据 | 本地停车原因、持续时间、当前路面/边界/障碍与候选依据 |
| V5 → V6 → 云端 | 异步场景请求 | 1–3 张原图、停车上下文、受限候选及事件封装 |
| 云端 → V6 → V7 | 结构化语义建议 | 场景判断、危险、不确定性、候选 ID 或 hold、解释 |
| V3 → V7 | 最新观测复核 | 更新的匹配帧、当前候选、几何与时效约束；这是必需的回路 |
| V7 → V8 | 融合决策 | 指令、来源、原因、候选/事件、帧序号和截止时间 |
| V8 → V9 | 受约束执行 | 通过最终门禁的动作；失败或过期则停止 |
| V9 → 环境 → V1 | 物理反馈 | 执行后重新获取真实观测 |
| 操作者 / 会话监督 → V8 | 停止与会话有效性 | 人工停止、会话/心跳等许可约束，不是自由 PWM 指令 |
| S2 → 记录与面板 | 原始传感器数据 | 雷达/深度记录及展示 |
| 记录系统 → 执行准入 | 记录健康 | 必需记录链的新鲜度/错误状态，不是雷达测距避障结论 |
| 各运行模块 → 实验记录 | 留证 | 观测、决策、请求回复、最终应用及版本关联 |

云请求/回复建议与本地控制流采用不同线型。颜色可辅助区分，但打印成灰度时仍应能辨识。实验数据流可集中汇入下方记录层，不必从每个小模块拉出交叉长线。

## 6. 云输入与输出合同

**输入：** 当前模型消费原图，历史不足时明确使用 1 或 2 帧，最多 3 帧；附当前停车原因、事件/帧上下文及车端已构造的候选。候选只针对当前帧；不使用旧图推断现在不可见的道路。不是连续视频上云。

**模型输出合同：** `road-recovery-v1`。

| 字段 | 含义 |
|---|---|
| `assessment` | 白色标记、右弯、道路模型缺口、障碍或未知等场景判断 |
| `recommendation` | `hold` 或 `try_candidate` |
| `candidate_id` | 选中的车端候选；hold 时为空 |
| `uncertain` / `hazards` | 不确定性与危险信息 |
| `reason` | 简短解释，仅用于记录/展示 |

事件绑定和收取时钟由车端管理，不能依赖模型自行生成执行身份。模型不提供 PWM、动作时长、任意目标坐标或“解除安全限制”指令。

## 7. 当前参数与实现性质

这些参数可放详细图注，不建议全部塞入主图。它们是当前软件配置，不代表已测得的物理安全边界。

| 参数 / 行为 | 当前配置或实现 |
|---|---|
| 恢复触发 | 持续停车至少 1 s，至少 3 个不同的新鲜观测 |
| 云输入策略 | `sparse3`，实际可为 1–3 帧 |
| 请求预算 | 单个在途请求；30 s 请求超时，最多 3 次尝试及有界重试 |
| 云辅助动作 | 本地短直行或小幅右旋 |
| 云短步软件上限 | 0.15 s / 5°，受最新观测和 IMU 等条件继续约束 |
| 四轮输出上限 | 30 PWM |
| 融合性质 | 规则驱动的决策级融合；不是神经网络特征融合或 PWM 加权平均 |
| 感知时序 | 异步推理；记录结果所属捕获帧，控制/应用时检查年龄 |

恢复阶段可抽象为：本地驾驶 → 停滞确认 → 云等待 → 当前证据复核 → 单步执行 → 再观察 → 本地恢复/保持停车。错误、超时或场景变化进入停车或重新核验；不要把它画成必然成功的单向流程。

## 8. 不应画为已实现功能的内容

- **时序掩码突变触发不是当前活动主链。** 旧 `cloud_arbitration` 分支有相关实现，但当前 profile 关闭；当前启用 `cloud_recovery`。恢复期间的 mask-change 检查用于场景变化失效处理，不能等同于论文目标触发方法已集成验证。
- **雷达/深度没有参与当前局部几何规划或 SLAM。** 当前是采集、记录、展示和记录健康检查。
- **没有可核验的自建云推理服务端。** `car/cloud_client/` 是车端客户端，不应放进云端部署框。
- **没有云端直接执行底盘控制。** 不画“云模型 → PWM / 电机”。
- **已撤回的功能不属于当前版本。** 独立 `road-environment-v1` 环境语义、后续连续回中、yaw 漂移补偿、越界锁定等不能混入本图。
- **没有在线学习闭环。** 实验归档和离线分析不自动反向训练模型。
- **控制约束不等于已验证安全性。** 当前仍有第三弯停车、出弯偏左等历史问题；图不能带有“全程自主成功”“保证不越界”等结论。
