# 场地颜色规则实现计划

用户明确指定本场地白色为可通过斑马线、黄色为不可跨越边界。采用本聊天直接实现，少量CPU检查与录制数据对照，不启动运动。

目标：YOLO仍决定可行驶区域及目标，颜色只解释其中lane头的路面标记，并额外排除黄色；不凭颜色生成YOLO未支持的道路。

- [x] 新 `perception/track_colors.py` 用当前消费帧分类：lane独立component具有白色支持、YOLO road支持且不接触黄色时释放；未分类lane保留，黄色无论lane是否预测都排除。颜色阈值与决策计数保存。
- [x] `yolopv2_semantic.py` 接收默认关闭的track_color_config，在匹配消费帧上分类，近车黄色加入hard-safe否决；边界携带effective exclusion mask，原始road/lane/frame归档不改。
- [x] `onboard.py` 只允许相机原坐标使用颜色辅助，把effective mask传给后续估计器，避免再次扣掉已确认白色标记；显示与CSV记录释放像素、黄色像素和近车黄线比例。
- [x] visual profile启用该场地规则，录制回放构造也读取开关；旧归档/default仍保留原规则。
- [x] 先复现白线阻断与缺失接口；检查白线放行、黄线未被lane预测仍排除、白黄冲突黄线优先、未知线保留、缺失帧/过期/障碍否决、不能扩展road。
- [x] 用0b2c18d8会话少量实际掩码比较道路有效性，保留原时效最终否决；统计颜色辅助CPU开销，保存source/input hash与增量，更新项目索引。下一次点击启动由新进程加载，无助手运动或服务重启。

限制：本场地规则，不是任意真实道路白线可跨越；亮度/色偏依本轮真实输入验证，未实测过斑马线或过弯。
